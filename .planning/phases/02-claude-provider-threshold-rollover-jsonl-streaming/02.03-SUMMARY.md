# Plan 02.03 — Anthropic OAuth + Keychain + QuotaWindow

## §S — Scope

Three responsibilities:

1. **Credential resolver** — locate Claude OAuth credentials with the precedence
   file → Keychain → env, tolerate both `claudeAiOauth` and `mcpOAuth` envelope
   shapes, treat empty strings as absent.
2. **OAuth client** — call `GET api.anthropic.com/api/oauth/usage` with the
   `anthropic-beta=oauth-2025-04-20` header for the live quota windows;
   call `POST platform.claude.com/v1/oauth/token` to refresh expiring tokens
   (client_id mirrors ClaudeBar's verified value).
3. **Domain extension** — add `QuotaWindow` + `UsageSnapshot.quotaWindows:
   [QuotaWindow]?` so Plan 02.04's provider has somewhere to put the windows.
   Default `nil`, Phase 1 + existing tests unchanged.

## §B — Backprop Notes

- B1: `UsageSnapshot` initializer gained `quotaWindows: [QuotaWindow]? = nil`
  as a trailing default — Phase 1 `OpenRouterProvider` snapshots continue to
  build without changes. If a future provider needs to require quotaWindows,
  drop the default and migrate call sites.
- B2: `postJSON` uses `keyEncodingStrategy = .convertToSnakeCase` on encode
  and `.convertFromSnakeCase` on decode — matching Anthropic's snake_case
  refresh-token payload. The GET path keeps `.convertFromSnakeCase` on decode.
- B3: Token in memory must be `Secret` (SEC-01). Logs and error descriptions
  must never include the token. The OAuth refresh POST body specifically
  contains `refresh_token` — never log the body (SEC-02 enforced by reading
  postJSON impl: only `url.path` + status emitted).
