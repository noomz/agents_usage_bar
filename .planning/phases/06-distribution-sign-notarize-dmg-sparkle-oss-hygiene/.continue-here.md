## Critical Anti-Patterns (do NOT repeat these)

- **ANTI-PATTERN: Adding a manual PBXCopyFilesBuildPhase "Embed Frameworks" for Sparkle SPM** → Xcode 16 SPM auto-embeds on macOS app target via `packageProductDependencies`. Manual phase tries to copy non-existent path and breaks build. Do not add this phase.
- **ANTI-PATTERN: Using `plutil -extract com.apple.security.network.client raw ...` with bare dots** → returns "No value at that key path" because plutil treats `.` as keypath separator. Use backslash-escaped form `'com\.apple\.security\.network\.client'`.
- **ANTI-PATTERN: Literal `--deep` or `altool` tokens in release.yml** (even in comments) → trips Plan 06-04 negative-grep gates. Reword as "recursive-deep-sign flag" / "deprecated pre-notarytool CLI".
- **ANTI-PATTERN: Using `hardendedRuntime` from RESEARCH.md** → typo in research; correct Apple key is `hardenedRuntime`. ExportOptions.plist already uses correct form — preserve it.
- **ANTI-PATTERN: Touching Entitlements.plist** → REL-09 + D-08 invariant. Entitlements remain byte-unchanged in Phase 6. entitlements-guard CI job (Plan 06-04) enforces.
- **ANTI-PATTERN: Adding `codesign --deep`, app-specific passwords, or `altool` to release.yml** → all explicitly forbidden by D-04 + research anti-patterns + Plan 06-04 acceptance gates.
- **ANTI-PATTERN: Writing Sparkle private key to disk** → must be piped via stdin: `echo "$SPARKLE_ED_PRIVATE_KEY" | sign_update --ed-key-file -`. Never `> /tmp/key`.
