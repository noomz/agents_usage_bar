|----------|-------------|
| user-provisioned secrets → GitHub | The human loads live Apple/Sparkle credentials; mishandling exposes signing/notarization authority |
| Sparkle feed → installed app | The live appcast + EdDSA-signed DMG are now consumed by real installs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-13 | Information Disclosure | secrets handled during provisioning | mitigate | Runbook uses `gh secret set` / web UI (encrypted at rest); temp p12/p8 deleted after encoding; private keys never committed |
| T-06-14 | Tampering | wrong/empty SUPublicEDKey ships → unverifiable updates | mitigate | Task 1 acceptance requires a non-placeholder base64 SUPublicEDKey; Sparkle rejects updates whose signature does not verify against it |
| T-06-15 | Spoofing | non-notarized DMG passes Gatekeeper | mitigate | Task 2 verifies via `spctl` + `stapler validate` + clean-account offline open before sign-off |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs; this plan is provisioning + live verification + a screenshot + a markdown UAT |
</threat_model>
