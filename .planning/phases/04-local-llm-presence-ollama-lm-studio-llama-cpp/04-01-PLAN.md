## Objective

Land the **non-actor foundation** every Phase 4 actor and view depends on. This plan ships four mechanical extensions:

1. `ProviderStatus.notRunning` enum case (CONTEXT D-01) — non-terminal, sandwiched between `.unauthenticated` and `.disabled`, mapped to gray via `StatusDot.dotColor` (LOCAL-04 muted-never-red).
2. Three `ProviderID` static constants — `.ollama`, `.lmstudio`, `.llamacpp` (CONTEXT Discretion §"`ProviderID` additions").
3. `ProviderStatus.classifyLocalhost(error:lastSuccess:)` static factory — maps the four connection-refused `URLError.Code` values to `.notRunning`; all other errors continue through `ProviderError.from(_:)` (RESEARCH §3.2 / LOCAL-05).
4. The `UsageSnapshot.raw[String: String]` carrier keys for locals are **documented** in the doc comment block: `"modelName"`, `"modelCount"`, `"vramBytes"`, `"allModels"` (pipe-separated), `"loadingModel"`, `"source"`. No new domain field per CONTEXT D-02a — the existing escape hatch is reused.

Nothing in this plan ships an actor; nothing emits an HTTP probe; nothing wires AppDependencies. This is the **enum / value-type / ripple** layer that wave-2 plans (04-04, 04-05, 04-06) consume immediately and wave-3 plans (04-07, 04-08) consume transitively.

       - Else → return `.error(<providerError>)`.

    Doc comment: cite LOCAL-05 + RESEARCH §3.2 explicitly: `/// Localhost-tier error classifier (Phase 4 / LOCAL-05). Returns .notRunning for the four URLError.Code values consistent with "server process not listening" (ECONNREFUSED + NXDOMAIN + RST + 2s-timeout). All other errors map via ProviderError.from(_:) to .stale (when prior success exists) or .error (cold start). HTTP 5xx never maps to .notRunning — the server IS running, it's just unhealthy. Composed by OllamaProvider / LMStudioProvider / LlamaCppProvider in Plans 04-04..06.`

    Do NOT add a new `ProviderError.Kind` case (Option B in RESEARCH §3.2 was explicitly rejected — the existing kinds suffice).
