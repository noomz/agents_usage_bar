## Objective

Build the **LM Studio provider actor** — probes `GET http://localhost:<port>/api/v0/models` first (LM Studio 0.3.5+ extended schema with `state` field) and falls back to `GET /v1/models` (OpenAI-compatible plain schema) on HTTP 404 from the extended endpoint. Folds the response into the same D-03 row states as Ollama (state A/B/C/D), but without the multi-model `+N more` flourish typical (LM Studio is single-model in practice). Reads the configurable port from `LMStudioConfig.port` (default 1234) injected at construction.

Satisfies LOCAL-02 (LM Studio probe + configurable port), LOCAL-04 (tri-state status), LOCAL-05 (connection-refused → notRunning), LOCAL-06 (no token tracking).

## Context

Per CONTEXT Discretion §"File layout" + §"One actor per runtime vs one unified `LocalProbeProvider`": one actor per runtime; mirrors `OllamaProvider` shape. Key divergence from 04-04 is the **fallback probe strategy** (RESEARCH §2.2):

1. `GET /api/v0/models` — LM Studio 0.3.5+ extended schema (Nov 2024); response carries per-model `state: "loaded" | "not-loaded"`. Filter on `state == "loaded"` to get the running set.
2. On HTTP 404 → fall back to `GET /v1/models` (OpenAI-compatible). No state field — treat ALL listed models as "loaded" (best effort, older LM Studio doesn't expose load state).

Per OQ-2 (RESEARCH §11), the fallback also fires on HTTP 500 for older LM Studio builds — Planner extends fallback to "ANY non-2xx from /api/v0/models triggers /v1/models retry". This is the safer interpretation given the wire-shape uncertainty.

Port is injected at init time. The composition root (Plan 04-08) reads `config.lmstudio.port` and constructs `LMStudioProvider(http: localhostHTTP, clock: clock, port: config.lmstudio.port)`.

Files referenced:
- `AgentsUsageBar/Providers/Ollama/OllamaProvider.swift` (post-04-04) — closest template; the actor shape is structurally identical except for the fallback chain.
- `AgentsUsageBar/Providers/Gemini/GeminiOAuthProvider.swift:154-267` — never-throws-for-transient discipline (STATE #82).
- `AgentsUsageBar/Providers/Ollama/Models/OllamaPsResponse.swift` (post-04-04) — lenient Codable template.

External API shape (RESEARCH §2.2):

**GET `/api/v0/models`** (LM Studio 0.3.5+):
```
{ "object": "list",
  "data": [
    { "id": "meta-llama-3.1-8b-instruct", "object": "model", "type": "llm",
      "publisher": "lmstudio-community", "arch": "llama",
      "compatibility_type": "gguf", "quantization": "Q4_K_M",
      "state": "loaded", "max_context_length": 131072, "loaded_context_length": 4096 } ] }
```

**GET `/v1/models`** (fallback):
```
{ "object": "list",
  "data": [ { "id": "meta-llama-3.1-8b-instruct", "object": "model", "owned_by": "organization_owner" } ] }
```

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| LM Studio updates its wire shape mid-version-bump (e.g. `state` becomes an enum object) | Lenient Codable + `state: String?` tolerates absence; future enum-shape change still produces nil → treated as "loaded" by `loadedModels` helper → state-C/D path. Worst case: model lists as loaded even when LM Studio reports a different state. UX impact: row never goes red. Locked by `v0Response_loadedModelsTreatsNilStateAsLoaded`. |
| OQ-2 disposition (any non-2xx fallback) catches an unexpected case — e.g. LM Studio returns HTTP 403 for an authenticated endpoint that doesn't exist for v0 | Safe by design: a fallback to /v1/models that ALSO returns 403 lands in the `degradedSnapshot` path → row shows .stale or .error (not .notRunning). The user-visible behavior matches the actual failure mode. |
| Cold-start: lastSnapshot is nil; first poll fails with HTTP 5xx | degradedSnapshot(now:underlying:) handles the nil-lastSnapshot branch: falls back to mutedNoData with the degraded tag. Same shape as Gemini STATE #82 cold-start path. |
| Test fixtures drift from real LM Studio output | RESEARCH §11 OQ-2 explicitly flags this; Plan 04-09 UAT (Test 2) re-verifies against a live LM Studio install in the reviewer's environment. |
| Concurrent /api/v0 + /v1 dispatch races inside FakeHTTPClient | Plan 04-05's fetch algorithm is SEQUENTIAL (v0 → on-failure → v1) — no `async let` between them. FakeHTTPClient still uses NSLock for thread-safety per STATE #83 (good hygiene). |
| Port collision with another local service on 1234 | Out of scope — user choice. config.toml override (`port = <int>`) is the documented escape valve (LOCAL-02 explicit). |
