## Objective

Wire all three local providers into `AppDependencies.makeProduction()` — the **single point** where Phase 4 actor instances actually get instantiated and start polling. Specifically:

1. Construct a **second** `URLSessionHTTPClient(timeoutSeconds: 2)` for the 1–2s localhost tier per POLL-08 split (Plan 04-03 made this constructible).
2. Register `OllamaProvider` conditionally on `config.ollama.enabled` (default true — always probes well-known port 11434 per LOCAL-01).
3. Register `LMStudioProvider` conditionally on `config.lmstudio.enabled` (default true — well-known port 1234 unless overridden per LOCAL-02).
4. Register `LlamaCppProvider` conditionally on `config.llamacpp.enabled && config.llamacpp.port != nil` (port REQUIRED per LOCAL-03 no-scanning); otherwise seed the **D-04 placeholder** carrying the discoverability subtitle `"Set [llamacpp] port in config.toml to enable"` (using the `placeholderMessage` parameter Plan 04-06 added to `seedPlaceholder`).

This plan also adds the **`ThresholdEngine` skip regression test** (RESEARCH §8.2): assert `ThresholdEngine.decisions(for: [localSnapshot])` returns `[]` because local snapshots have `quota == nil` (Plan 02-05 / `ThresholdEngine.swift:124` guard already handles this — the test is a regression lock per CONTEXT canonical-refs Pitfall 6).

Plus the **`AggregateStoreLocalRollupTests` regression**: verify `rollupTotals()` skips providers with `capabilities.hasTokens == false` (Phase 3 D-07 / STATE #86) — locals (`hasTokens: false`) are auto-excluded from "Today total" — already implemented; the test is a lock against future regressions.

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Adding two `URLSessionHTTPClient` instances doubles memory cost or socket pool | URLSession default httpMaximumConnectionsPerHost = 6; two instances × 6 = 12 worst-case sockets. Each has its own queue, but for localhost-only probes (3 actors × 1-3 requests per poll = 3-9 in-flight max) this is well within ulimit. No measurable memory impact. |
| Cold-launch placeholder rows for Ollama / LM Studio show `.notRunning` "Not running" BEFORE the first probe — confusing UX when the user IS running ollama serve | Acceptable trade — the user sees the row appear immediately, then transitions to .ok within 5s (POLL-03 popover-open refresh coalesces under 5s). The alternative (no placeholder) would show ZERO Ollama row until the first poll — worse UX. Plan 04-09 UAT Test 1 verifies the transition. |
| llama.cpp port specified but server not listening — placeholder still seeds (because llamacppRegistered is true and the actor takes over) | Correct: actor registers, first probe yields `.notRunning` (connection refused → classifyLocalhost → .notRunning), row renders "Not running". This is the expected ROADMAP SC#4 behavior. |
| Phase 3 makeProduction smoke test (STATE #87 relaxed assertion) breaks because the new placeholder seeds change the popover row count | Smoke test in Plan 04-08 explicitly asserts the new ProviderID.ollama / .lmstudio / .llamacpp entries appear. Phase 3 test (`AppDependenciesCodexGeminiRegistrationTests.makeProduction_smoke`) was already relaxed to "OpenRouter placeholder present + makeProduction runs without throwing" — STILL holds because the new providers don't displace the existing four. |
| ThresholdEngine accidentally fires a notification for a local snapshot if the actor stamps a non-nil quota | Locked by negative invariant: every local actor's source-grep test (Plan 04-04/05/06) asserts `quota: nil` in the snapshot construction. The ThresholdEngine `quota == nil` guard at line 124 is the second line of defense; locked by `ThresholdEngineLocalNilQuotaTests`. |
| AggregateStoreLocalRollupTests asserts hasTokens=false providers contribute 0 — but Plan 04-04/05/06 actors might forget to set capabilities.hasTokens = false | The actor capabilities declaration is per-plan; each plan has an acceptance criterion grep verifying `hasTokens: false`. Plan 04-08's regression test is the integration lock. |
| OPTION A (placeholder-then-replace) introduces a brief UI flash from "Not running" → real state on first poll | The replacement is atomic (a single `apply()` call updates the row from one ProviderState to another). SwiftUI `@Observable` re-renders the affected row only; no popover-level flash. Plan 04-09 UAT Test 1 verifies the transition is visually clean. |
| LOCAL-06 anti-feature accidentally violated at the composition layer (e.g. somebody adds a `tokensToday` calculation in the registration code) | Verification grep on `AppDependencies.swift`: `grep -E 'tokensToday.*ollama|tokensToday.*lmstudio|tokensToday.*llamacpp'` returns 0. Composition root does no per-provider computation; it just registers actors. |
